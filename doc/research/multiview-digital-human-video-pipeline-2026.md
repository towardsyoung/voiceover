# 多视图数字人 + 克隆音色 + 分镜视频生成推荐方案

> 调研与方案日期：2026-08-14  
> 输入：数字人多角度四视图、场景多角度四视图、经授权的声音样本、业务主题/素材。  
> 输出：由克隆音色播报、人物和场景尽量一致、按分镜生成并剪辑完成的口播视频。

如果目标已经收敛为单人坐姿、固定机位、一分钟以内，并要求用户只上传人物图、场景图、声音样本和文案，请直接参阅 [简单输入的一分钟坐姿数字人口播方案](./simple-input-seated-avatar-pipeline-2026.md)。

## 一、推荐结论

这条链路可行，但最推荐的不是“所有镜头都交给一个通用视频模型”，而是下面的混合方案：

```text
人物/场景四视图资产定版
  → 口播文案与分镜一起规划
  → TTS 生成最终音频并锁定时长
  → 为每个分镜生成经过资产约束的首帧/尾帧
  → 按镜头类型选择生成引擎
       ├─ 稳定正面口播：MuseTalk 1.5 / LatentSync 1.6
       ├─ 有动作的动态口播：Seedance 2.0 / Kling 3.0 Omni
       ├─ 自建单图动态口播：LongCat-Video-Avatar 1.5 / InfiniteTalk
       └─ 空镜、产品、环境 B-roll：Veo 3.1 / Seedance / Kling
  → 使用原始 TTS 替换音轨
  → 必要时 LatentSync 二次校正嘴部
  → 剪辑、字幕、包装、音频混合和质检
```

建议镜头配比：

- **60%–75% 稳定口播镜头**：固定/轻微运镜、胸像或近景，用 MuseTalk/LatentSync，确保身份和口型。
- **15%–25% 动作口播镜头**：转身、走动、换景、拿产品、明显手势，用 Seedance/Kling/LongCat。
- **10%–20% B-roll**：场景、商品特写、图表、屏录和空镜，不让数字人一直占满画面。

这一配比不是硬限制。核心原则是：**通用视频模型只生成它擅长且值得付费的镜头，不负责全片每一秒。**

## 二、三档可选落地方案

### 方案 A：综合效果最好，推荐作为首个 PoC

| 环节 | 推荐组件 | 理由 |
|---|---|---|
| 文案 | 支持结构化输出的 LLM | 同时输出口播稿、情绪、停顿、镜头意图和资产引用 |
| TTS | MiniMax Speech API 或 IndexTTS2 | MiniMax 上手快；IndexTTS2 情绪和时长控制强 |
| 分镜 | 4–15 秒一个视频组 | 与主流视频模型片段长度相符，方便失败重试和镜头替换 |
| 关键帧 | 一致性图像模型 + 人物/场景四视图 | 先把每镜构图定死，减少视频模型重新设计人物和场景 |
| 动态口播 | Seedance 2.0 Reference-to-Video | 可同时参考文本、图像、音频和视频，适合把 TTS、人物和场景一起作为条件 |
| 一致性备选 | Kling VIDEO 3.0 Omni Subject Binding | 支持多角度人物参考/短视频绑定，适合跨镜人物一致性 |
| 口型修复 | LatentSync 1.6 | 将通用视频模型的最终嘴部重新对齐原始 TTS |
| 稳定口播 | MuseTalk 1.5 | 大量正面口播无需承担通用视频生成成本 |

推荐原因：Seedance 2.0 官方采用统一音视频多模态架构，支持文字、图像、音频和视频参考，正好匹配“人物四视图 + 场景四视图 + TTS + 分镜”的输入形态。[官方发布说明](https://seed.bytedance.com/blog/seedance-2-0-official-launch)

限制：

- 单次通常只生成 4–15 秒，完整视频必须按分镜拼接。
- 社区有[“上传音频被模型改写部分语音”的反馈](https://www.reddit.com/r/Seedance_AI/comments/1v4cba5/how_can_i_force_seedance_20_to_use_my_uploaded/)，因此必须保存原始 TTS，并在成片阶段重新覆盖音轨和检查口型。该反馈只作为风险线索，仍需用自己的语言、音色和账户版本复测。
- 720p 参考生成公开 API 约为 $0.3024/秒；全片使用成本很高。
- 通用视频模型仍可能改变服装细节、五官、场景布局和道具文字。

### 方案 B：效果优先、人物一致性优先

| 环节 | 推荐组件 |
|---|---|
| TTS | MiniMax Speech / 经授权的商业声音克隆服务 |
| 人物约束 | Kling 3.0 Subject Binding，输入多角度照片或短转身视频 |
| 动态口播 | Kling VIDEO 3.0 Omni，优先 720p 试片，定版再 1080p |
| 空镜/B-roll | Veo 3.1 Ingredients to Video 或 Seedance 2.0 |
| 精确口型 | 使用原始 TTS 音频做 LatentSync 1.6 后处理 |

[Kling 3.0 Subject Binding](https://kling.ai/blog/kling-3-subject-binding-character-consistency) 明确建议上传多角度参考图或短视频，以便模型在视角变化中维持人物特征。官方 Video 3.0 价格以 credits 计：720p 原生音频 9 credits/秒、1080p 12 credits/秒；不同套餐的 credits 单价不同，必须按账户实际折算。[Kling VIDEO 3.0 官方指南](https://home.kling.ai/quickstart/klingai-video-3-model-user-guide)

Veo 3.1 最多接受三张同一人物、角色或产品的资产参考图，并能原生输出音频，但不适合作为精确复用外部克隆 TTS 的主口播引擎。更适合场景建立、产品演示和无台词镜头。[Google Veo 3.1 API 文档](https://ai.google.dev/gemini-api/docs/veo)

### 方案 C：尽量自建、降低长期边际成本

| 环节 | 推荐组件 | 注意事项 |
|---|---|---|
| TTS | CosyVoice 3 | Apache-2.0，支持多语言、中文方言/口音、跨语种零样本克隆 |
| 备选 TTS | IndexTTS2 | 情绪与音色解耦、时长控制适合视频；采用 Bilibili Model Use License，大规模公司需额外授权 |
| 稳定正面口播 | MuseTalk 1.5 | 默认量产引擎 |
| 精品正面口播 | LatentSync 1.6 | 更慢但嘴部细节更强 |
| 动态单图口播 | LongCat-Video-Avatar 1.5 | MIT；支持音频驱动、720p、INT8、8 步蒸馏，但部署重 |
| 动态备选 | InfiniteTalk | Apache-2.0，社区成熟，长片慢 |
| 实时/流式备选 | SoulX-FlashHead Lite | 新项目；4090 官方报告可实时，但需生产压测 |

自建方案不能直接把人物四视图全部喂给 LongCat/InfiniteTalk 并期待稳定绑定。更可靠的方法是：

1. 利用四视图为每个镜头生成一张已经定好人物姿态、服装、机位和场景的规范首帧。
2. 视频模型只负责从该首帧产生短时动作。
3. 每个镜头继续输入最终 TTS 音频。
4. 对口型不合格的镜头用 LatentSync 重做嘴部。

这会比商业 Seedance/Kling 多出关键帧生成、模型部署和后处理工作，但长期大量生成的边际成本更低，素材也不必上传第三方平台。

## 三、TTS 选择

### 首选：CosyVoice 3（自建和商用友好）

[CosyVoice 官方 GitHub](https://github.com/QwenAudio/CosyVoice) 为 Apache-2.0。适合中文、多语言、方言/口音和跨语言声音克隆，且有完整训练与部署工具链。

适用：

- 需要私有部署。
- 月生成量较大。
- 中文、方言或中英混读。
- 希望避免按字符持续付费。

### 情绪与时长控制：IndexTTS2

[IndexTTS2 官方 GitHub](https://github.com/index-tts/index-tts) 支持音色和情绪分离，并强调精确时长控制，尤其适合让台词长度适配既定分镜。

授权注意：它不是简单的 Apache/MIT。Bilibili Model Use License 对年收入超过人民币 10 亿元或月活超过 1 亿的主体要求另行获取授权，并规定了下游分发等义务。正式商业使用前应由法务检查完整条款。

### 快速上线：MiniMax Speech API

优点是中文效果、声音克隆、情绪指令和接口成熟，无需维护 GPU。适合 PoC 和中小用量。要确认账户对应的声音授权、数据保留和商用条款。

### TTS 必须先于视频锁定

正确顺序：

```text
文案定稿 → TTS 生成 → 音频人工/自动质检 → 得到精确时长 → 再做最终分镜和视频
```

不要先按文字估算时长生成视频，再补 TTS。不同音色、情绪和语速会让同一句话的长度差异很大，后补音频会破坏动作节奏和口型。

## 四、四视图资产应该怎样制作

### 人物资产包

最低建议不只是四张“头像”，而是：

| 资产 | 要求 |
|---|---|
| 正面全身 | 中性站姿，手和鞋完整，无遮挡 |
| 左 45°/侧面 | 与正面服装、发型、光线一致 |
| 右 45°/侧面 | 与正面一致 |
| 背面/后 45° | 清楚展示发型和服装背部 |
| 正面胸像 | 口鼻、牙齿、眼睛细节清晰，供近景使用 |
| 表情板 | 中性、微笑、严肃、惊讶；不要变化成不同人物 |
| 服装细节 | Logo、领口、饰品、手表、鞋等局部特写 |
| 可选转身视频 | 5–10 秒缓慢转身，往往比四张离散图片更适合 Subject Binding |

所有图片应统一：年龄、脸型、发型、服装、配饰、妆容、身材比例、光照方向和色温。四张分别生成、但没有经过一致性校验的图片，不能算可靠四视图。

### 场景资产包

| 资产 | 作用 |
|---|---|
| 建立镜头 | 展示完整空间布局 |
| 正向视图 | 明确主播主机位和背景 |
| 左向/右向视图 | 为转身、侧拍、移动镜头提供空间参照 |
| 反向视图 | 避免镜头反打时凭空生成另一间房 |
| 平面示意图 | 标出人物、桌椅、窗、门、灯和产品位置 |
| 材质/道具特写 | 固定桌面、墙面、Logo、商品和屏幕内容 |

对场景一致性而言，平面布局图常常比第四张漂亮效果图更有价值。它能明确“门在左边、窗在后方、桌子距离和人物动线”，减少跨镜空间翻转。

### 不要把八张图机械拼成一张后直接使用

- 支持多参考输入的模型，应分别上传并在提示词中明确 `@Image1` 是人物正面、`@Image2` 是人物左侧、`@Image5` 是场景建立镜头。
- 只支持少量参考图的模型，可以制作“身份板”和“场景板”，但每块图要大、清楚、无文字遮挡，避免每个格子分辨率过低。
- 人物和场景最好分开，不要让模型误把四视图排版也生成到视频画面里。

## 五、文案与分镜的数据结构

文案模型不应只输出一段自然语言。建议生成下面的结构化中间数据：

```json
{
  "project": {
    "aspect_ratio": "9:16",
    "target_duration_sec": 60,
    "style": "真人写实、自然商业摄影"
  },
  "voice": {
    "speaker": "数字人A",
    "emotion": "可信、亲切",
    "speed": 1.0
  },
  "shots": [
    {
      "shot_no": 1,
      "duration_sec": 6.5,
      "scene": "演播室正向机位",
      "character": "数字人A",
      "dialogue": "这里放最终口播原文。",
      "shot_size": "中近景",
      "camera": "固定，极轻微 Dolly In",
      "action": "正视镜头，右手做一次克制的解释手势",
      "orientation": "正面偏左十五度",
      "emotion": "自然、自信",
      "character_refs": ["front_bust", "front_full", "right_45"],
      "scene_refs": ["studio_front", "studio_layout"],
      "engine": "musetalk_or_seedance",
      "first_frame_prompt": "...",
      "video_prompt": "..."
    }
  ]
}
```

实际送给视频模型时，按 `storyboard-lite` 的规则组织：

- 每个视频组必须为 **4–15 秒**。
- 每组内部时间码从 `[0s]` 重新开始。
- 台词必须和最终 TTS 文本逐字一致。
- 每个时间段包含画面、运镜和声音。
- 明确角色朝向、左右关系、动作承接和尾帧状态。
- 不要在视频模型里生成字幕、Logo 和精确小字；这些放到后期。

口播时长估算可作为初稿：正常中文约 3 字/秒，愤怒或快速约 4 字/秒，悲伤、耳语或虚弱约 2 字/秒，再留约 1 秒动作和呼吸。但最终必须以 TTS 实际音频为准。

## 六、按镜头选择模型，而不是全片固定一个模型

| 镜头 | 推荐引擎 | 原因 |
|---|---|---|
| 正面胸像、连续解释 | MuseTalk 1.5 | 最便宜、身份最稳、可生成长台词 |
| 嘴部近景、发音要求高 | LatentSync 1.6 | 嘴部纹理和口型精修 |
| 明显手势、转身、走动 | Seedance 2.0 / Kling 3.0 | 通用视频模型更擅长整帧动作 |
| 单图人物带半身动作、自建 | LongCat-Video-Avatar 1.5 | 音频直接驱动，MIT |
| 产品拿取和互动 | Seedance/Kling，短镜头多生成几版 | 手部仍是高风险，应缩短镜头并留备选 |
| 无人物场景建立 | Veo/Seedance/Kling | 不需要支付口型和身份一致性的额外复杂度 |
| 图表、产品参数、字幕 | 后期合成 | 生成模型不适合精确文字和数据 |

## 七、音频和口型的正确处理

即使 Seedance/Kling 支持原生音频，也建议把“原始克隆 TTS”视为唯一母版：

1. 为每个分镜切出精确的 TTS 音频片段。
2. 把该音频作为视频生成条件。
3. 保留模型生成的环境音和动作音，但不要默认采用它重新生成的角色声音。
4. 将最终视频中的对白轨替换为原始 TTS。
5. 对比嘴部是否仍与原始 TTS 对齐。
6. 不对齐时，用 LatentSync 1.6 对最终选中的画面重新做口型。
7. 最后再混入环境声、动作声和音乐。

如果视频模型大幅改写了台词节奏，LatentSync 也无法修复整个人的动作节拍。这类片段应重生成，而不是无限后处理。

## 八、成本判断

### 全片 Seedance 生成为什么贵

[fal 的 Seedance 2.0 Reference-to-Video 定价](https://fal.ai/models/bytedance/seedance-2.0/reference-to-video)显示，720p：

- 标准、无视频输入：$0.3024/秒。
- Fast、无视频输入：$0.2419/秒。
- 标准、有视频输入：$0.1814/秒。
- Fast、有视频输入：$0.1452/秒。

理论上的一分钟输出成本：

```text
标准参考图生成：60 × $0.3024 = $18.14/分钟
Fast 参考图生成：60 × $0.2419 = $14.51/分钟
```

如果平均每个镜头生成 2–3 次才选中一版，实际可用成片分钟可能达到 `$30–50+`。因此 Seedance 更应该承担少量关键镜头，而不是替代整条口播流水线。

### 混合方案示例

假设一条 60 秒视频：

- 40 秒 MuseTalk 稳定口播。
- 12 秒 Seedance 动态口播。
- 8 秒 B-roll，由较便宜的图生视频模型或已有素材完成。

Seedance 标准 720p 的理论生成费约 `12 × $0.3024 = $3.63`；即使动态镜头平均重试两次，也比整段 60 秒全部用 Seedance 更可控。MuseTalk 的纯 GPU 成本相对于通用视频模型几乎可以忽略。

## 九、推荐的最小可行版本

第一阶段不要同时接十个模型。建议只做下面五个组件：

1. **CosyVoice 3 或 MiniMax Speech**：生成最终克隆音频。
2. **结构化文案/分镜生成器**：输出 4–15 秒视频组和资产引用。
3. **MuseTalk 1.5**：承担默认正面口播。
4. **Seedance 2.0 Reference-to-Video**：承担需要动作和换景的镜头。
5. **LatentSync 1.6**：承担精品和失败口型修复。

Kling、LongCat、InfiniteTalk 和 Veo 先作为 A/B 备选，不应在 MVP 首版全部集成。

## 十、PoC 验收标准

使用同一人物、同一场景和同一段最终 TTS，制作一条 45–60 秒样片，至少包含：

- 2 个正面口播镜头。
- 1 个侧向口播镜头。
- 1 个明显手势镜头。
- 1 个拿产品或指向道具的镜头。
- 1 个场景空镜/B-roll。
- 1 次景别或机位切换。

记录：

| 指标 | 验收建议 |
|---|---|
| 人物一致性 | 盲评中至少 80% 认为是同一人物；五官、发型、服装无明显漂移 |
| 场景一致性 | 门窗、桌椅、光源和人物站位跨镜不翻转 |
| 口型 | 快速中文、闭口音和爆破音无明显错位 |
| 声音 | 音色稳定，无吞字、异常重音和跨句情绪跳变 |
| 动作 | 手指、手腕、拿物、转身无明显畸形或瞬移 |
| 成功率 | 每镜平均生成次数不超过 2.5 次 |
| 成本 | 记录“总生成费用 / 最终可用秒数”，而不是只记 API 标价 |
| 工时 | 记录人工选片、重做、口型修复和剪辑时间 |

## 十一、最终建议

如果现在就开始实施，我建议采用：

> **CosyVoice 3/MiniMax Speech + 结构化分镜 + MuseTalk 1.5 + Seedance 2.0 + LatentSync 1.6。**

职责划分：

- CosyVoice/MiniMax：锁定经授权的声音和最终节奏。
- 分镜层：把长文案拆成 4–15 秒、可重试、可替换的镜头任务。
- MuseTalk：生成大部分稳定、便宜的口播。
- Seedance：只生成需要全身动作、明显手势、转身和场景变化的关键镜头。
- LatentSync：将最终选中的动态画面重新对齐原始 TTS。

如果更看重人物跨镜一致性，可把 Seedance 换成 Kling 3.0 Omni；如果更看重私有部署，则用 LongCat-Video-Avatar 1.5 替换 Seedance，但要接受更高的部署复杂度和较慢的生成。

这套设计使用了分镜技能中的 4–15 秒视频组、最终台词不改写、逐段时间码、朝向/空间连续性和尾帧承接规则。它们会直接影响生成成功率，而不只是让分镜文档更好看。
