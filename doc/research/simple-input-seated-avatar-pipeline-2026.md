# 简单输入的一分钟坐姿数字人口播方案调研

> 调研日期：2026-08-14  
> 用户输入：人物图、场景图、口播人声音样本、口播内容。  
> 输出：人物坐在演播室/椅子等固定场景中，连续口播约 1 分钟的视频。  
> 目标：输入尽量少、自动化程度高、人物和场景稳定、中文口型可靠、成本可控。

## 一、结论

对于“人物不走动、固定机位、一分钟口播”，不建议使用 Seedance、Kling、Veo 等通用视频模型逐镜生成整段视频。最适合的是专门的长时音频驱动头像模型。

推荐优先级：

1. **第一版/最快上线：Hedra Avatar**。
2. **商业质量对照：HeyGen Photo Avatar**。
3. **低价商业对照：D-ID**。
4. **自建新路线：SoulX-FlashHead Lite**。
5. **自建稳妥路线：动作模板 + MuseTalk 1.5；精品任务切换 LatentSync 1.6**。
6. **LongCat-Video-Avatar 1.5 只作为后续“更明显半身动作”的实验方案，不作为第一版主链路**。

最推荐的产品架构：

```text
人物图 + 场景图
  → 自动生成一张“人物坐在目标场景”的标准起始图

声音样本 + 口播内容
  → 声音克隆 TTS
  → 最终一分钟音频

标准起始图 + 最终音频
  → Hedra Avatar（首版）
  → 口型/身份/画面质检
  → 字幕、Logo、背景音乐、片头片尾
  → 成片
```

等业务量和质量标准稳定后，再决定是否迁移到自建 SoulX-FlashHead 或 MuseTalk 管线。

## 二、为什么这次不需要复杂分镜视频模型

本场景有几个有利条件：

- 只有一个人物。
- 人物处于坐姿，不走动。
- 场景固定。
- 机位可以固定或只有轻微推拉。
- 视频约一分钟。
- 核心诉求是说话自然、嘴对得准、人物不能漂。

通用视频模型的主要价值是走动、表演、镜头调度、物体交互和场景变化。把它们用于一分钟固定坐姿口播，反而会引入：

- 一分钟内五官、服装和背景逐渐变化。
- 手指、椅子、桌面、Logo 等结构发生畸变。
- 每 5–15 秒需要重新生成和拼接。
- 镜头接缝、人物姿态和光线不连续。
- 通用视频生成费用远高于专用头像模型。

因此，第一版应把整段口播看成“一张稳定起始图 + 一条最终音频”的长时头像任务，而不是影视级多镜头任务。

## 四、首选：Hedra Avatar

[Hedra Avatar 官方模型页](https://www.hedra.com/models/video/hedra/avatar)显示：

- 输入是一张 start frame 和一条音频。
- 输出时长由音频决定。
- 最长支持 10 分钟。
- 支持 1:1、16:9、9:16。
- 支持 540p、720p、1080p。
- 官方定价为 7 credits/秒。
- 可以通过行为提示词控制微动作，如自然手势、偶尔微笑、友好放松。

[Hedra 文件规格](https://www.hedra.com/docs/pages/app/troubleshooting/file-specifications)显示付费计划音频/视频最长可达 10 分钟，Hedra Avatar 本身的限制为 10 分钟，因此一分钟内容在产品支持范围内。

它与本需求高度匹配：

```text
用户上传人物图
用户上传场景图
系统生成 seated_anchor.png
系统克隆声音并生成 narration.wav
Hedra Avatar(seated_anchor.png, narration.wav)
```

### 成本粗算

一分钟视频消耗：

```text
60 秒 × 7 credits/秒 = 420 credits
```

按 2026-08 检索到的 Hedra 订阅：

- Basic：$15/月，1,500 credits，满额约 3.57 分钟，即约 $4.20/分钟。
- Creator：$30/月，5,400 credits，满额约 12.86 分钟，即约 $2.33/分钟。
- Professional：$75/月，14,400 credits，满额约 34.29 分钟，即约 $2.19/分钟。

月度 credits 不结转，因此真实单价取决于额度利用率。价格需在采购当日回到 [Hedra Pricing](https://www.hedra.com/pricing) 重新确认。

### 为什么首版优先它

- 不需要自己部署 13B 视频模型。
- 一分钟可以一次生成，不必切成六到十二段。
- 用户已有最终口播内容和声音样本，内部只需补 TTS。
- 起始图中已经包含人物、椅子和场景，模型不需要重新设计空间。
- 模型专门针对 talking avatar，而不是泛化电影镜头。

### 风险

- 只上传头像大头照时，模型无法可靠推断完整坐姿和椅子；必须先生成/合成标准起始图。
- 一分钟手势可能重复或略显模板化。
- 行为提示词需要限制动作，否则手靠近脸、桌面和椅子时可能变形。
- 商业服务存在价格、队列、内容审核和数据上传风险。

推荐行为提示词：

```text
The presenter remains seated throughout the entire video, facing the camera.
Natural blinking, subtle breathing, small head movements, and restrained hand gestures below chest level.
Calm and professional delivery. No standing up, no walking, no large body movement,
no hand covering the face, and no camera angle change.
```

## 五、商业对照方案

### HeyGen Photo Avatar

[HeyGen Photo Avatar API](https://developers.heygen.com/photo-avatar)支持从单张正面照片创建口型同步视频。付费计划页面列出的单视频最大时长可达 30 分钟，一分钟完全可覆盖。[HeyGen 计划限制](https://www.heygen.com/pricing)

优点：

- 产品成熟，API、任务状态、素材管理和编辑器较完整。
- 人脸和口型商业观感通常较好。
- 可以直接使用脚本/声音，也支持音频输入能力。
- API Photo Avatar 720p/1080p 公开价约 $3/分钟。

注意：

- Avatar V 的最佳体验依赖约 15 秒视频参考，它不是本项目“一张人物图”的严格最简输入；首测应使用 Photo Avatar。
- 场景图仍需要先和人物图合成为最终起始画面，或在编辑器中作为背景处理。
- 自定义数字分身和部分高级 API 能力可能需要更高套餐/企业权限。

建议把 HeyGen 用作质量上限对照，而不是首版唯一供应商。

### D-ID

[D-ID API](https://www.d-id.com/api/)明确支持人物图片加自有音频生成数字人口播，[Create a Talk API](https://docs.d-id.com/reference/createtalk)接受 `source_url` 和 AudioScript。

优点：

- API 简单。
- 自有音频接入直接。
- 公开套餐折算约 $0.69–0.78/分钟，低于 Hedra 和 HeyGen。
- 适合快速验证完整业务流程。

缺点：

- 画面更偏传统“照片说话”。
- 肩膀、身体和手势的自然度通常不是它的核心优势。
- 部分套餐有水印；按 15 秒进位可能抬高短视频成本。

如果目标是“先证明用户会使用”，D-ID 可以作为最低成本的商业基线；如果目标是展示效果，优先 Hedra/HeyGen。

## 六、自建方案

### 路线 1：SoulX-FlashHead Lite

[SoulX-FlashHead 官方 GitHub](https://github.com/Soul-AILab/SoulX-FlashHead)的 Lite 模型为 1.3B，支持单图、音频、无限流式生成。官方报告在单张 RTX 4090 上可达 96 FPS，或同时生成三路 25 FPS 实时视频。

它比 LongCat/InfiniteTalk 更适合本项目的原因：

- 模型更小。
- 目标就是长时、流式、固定肖像。
- 一分钟不需要拆成许多独立扩散片段。
- 4090 级显卡可用，不需要 48/80 GB 起步。

主要风险：

- 2026 年新项目，生产案例和第三方压测较少。
- Lite 与 Pro 画质有差距；Pro 在单 4090 上只有约 10.8 FPS。
- 仍需自己处理 API 服务、显存、队列、音频编码、视频编码和失败恢复。
- 必须实测中文快速语速、牙齿、胡须、侧脸和一分钟漂移。

建议：作为自建 A/B 的第一候选，但不要未经 PoC 就替代商业主链路。

### 路线 2：动作模板 + MuseTalk 1.5

这是成本最低、风险最容易控制的自建方案：

```text
标准起始图
  → 使用内部授权的坐姿动作模板驱动头像
  → 得到 3–5 段 10–20 秒无声坐姿底片
  → 自动按台词情绪选择、拼接和交叉淡化底片
  → MuseTalk 1.5 按最终 TTS 重绘嘴部
  → 输出一分钟视频
```

动作模板可以是：

- 中性倾听、轻微眨眼和呼吸。
- 轻微点头。
- 右手一次小幅解释手势。
- 左手一次小幅强调手势。
- 微笑后回到中性。

优势：

- 人物和场景大部分像素来自固定起始图/底片，漂移小。
- MuseTalk 推理非常便宜。
- 一分钟没有扩散模型不断重画背景的问题。
- 手势库可以人工审核，一次制作、反复复用。

不足：

- 动作不会真正理解每句话语义，只能按段落情绪选择模板。
- 单张图生成的身体动作仍需一个肖像/动作驱动模型。
- 动作模板重复时容易被用户察觉，需要至少 3–5 个版本和合理调度。

这是高产量业务最值得长期建设的方案。

### 路线 3：LongCat-Video-Avatar 1.5

[LongCat-Video-Avatar 1.5](https://github.com/meituan-longcat/LongCat-Video)支持 Audio-Text-Image-to-Video，使用 Whisper-large-v3、8 步蒸馏、INT8 和 480p/720p，模型权重为 MIT。[技术报告](https://arxiv.org/abs/2605.26486)强调长视频、口型和身份稳定性。

它适合：

- 希望人物上半身动作明显。
- 不满足于只动嘴和头部。
- 能接受 13B 级视频模型部署和更慢生成。

它不适合作为第一版的原因：

- 本需求不需要大量身体运动。
- 计算量远高于 MuseTalk/FlashHead Lite。
- 整帧生成仍比局部口型模型更容易改变场景和人物细节。
- 一分钟成功并不等于每条输入都能一次出片。

### 暂不推荐：LiveAvatar 14B、StableAvatar、InfiniteTalk

- [Alibaba LiveAvatar](https://github.com/Alibaba-Quark/LiveAvatar)支持无限流式，但单卡最初需要 80 GB，FP8 优化仍偏向 48 GB；对第一版过重。
- StableAvatar 支持无限长度，但社区/官方都承认生成时间较长，工程成熟度不如商业服务。
- InfiniteTalk 更适合明显全身动作、视频配音和复杂动态；固定坐姿口播没有必要承担 Wan 14B 的成本。

## 七、四项输入的自动处理

建议 API 只暴露：

```json
{
  "person_image": "人物图片",
  "scene_image": "演播室或房间图片",
  "voice_sample": "经授权的声音样本",
  "script": "一分钟以内的口播内容"
}
```

内部自动完成以下步骤。

### 1. 输入检查

- 人物图至少 1024px，脸部清楚，无严重遮挡。
- 声音样本建议 15–30 秒，单人、无音乐、无混响、无环境噪声。
- 记录人物肖像和声音克隆授权。
- 口播内容做敏感内容和长度检查。

### 2. 生成标准起始图

如果人物图本身不是坐姿且与场景分离，系统必须先生成：

```text
seated_anchor.png
```

起始图要求：

- 人物坐在椅子/演播台前。
- 正面或偏转不超过 15°。
- 胸像或腰部以上构图。
- 双手自然放在桌面、扶手或画面下方。
- 不让手遮挡脸部。
- 保持人物五官、发型、服装和年龄。
- 场景布局、品牌色和光照保持不变。
- 9:16 或 16:9 直接按最终比例生成。
- 不在生成图中加入字幕、Logo 小字或商品参数。

可以使用多参考图像编辑模型完成“人物放入场景”，然后自动做人脸相似度、脸部清晰度、手部和构图检查。若人物图本身已经是在目标场景中的坐姿成片，可以跳过这一步。

### 3. 生成最终 TTS

推荐两档：

- **最快上线：MiniMax Speech 等商业声音克隆 API**。
- **自建：[CosyVoice 3](https://github.com/QwenAudio/CosyVoice)**，Apache-2.0，适合中文、多语言和跨语言声音克隆。

TTS 前进行文本规范化：

- 数字、日期、金额和百分比。
- 英文缩写。
- 多音字。
- 标点和呼吸停顿。
- 超长句拆分。

输出保留 WAV 母版；视频模型生成后不能采用被模型改写过的对白替换母版。

### 4. Avatar 生成

首版直接将完整一分钟音频作为一次任务提交 Hedra Avatar。不要没有必要地拆成 5–10 秒片段。

只有以下情况才拆段：

- 某一段需要不同情绪。
- 中间要插入产品图/B-roll。
- 一次生成失败或后半段明显漂移。
- 需要替换某一句内容而不重做整分钟。

推荐拆分粒度为 15–30 秒，而不是通用视频模型常用的 5 秒。

### 5. 后处理

- 使用原始 TTS 作为最终对白轨。
- 自动生成字幕，但字幕由后期渲染，不由视频模型生成。
- 添加 Logo、标题条、商品图和背景音乐。
- 标准化响度。
- 输出 1080p H.264/H.265。

## 八、自动质检

每个任务至少检查：

| 检查 | 方法 | 失败处理 |
|---|---|---|
| 人脸是否同一人 | 人脸 embedding 相似度抽帧检查 | 重新生成起始图或 Avatar |
| 口型同步 | SyncNet/AV offset + 句首句尾检查 | LatentSync 修复或重生成 |
| 场景漂移 | 背景特征/关键区域差异 | 重生成；降低行为动作强度 |
| 手部异常 | 手部关键点/抽帧模型 | 重生成；将手移到画面下方 |
| 音频内容 | ASR 回转录与原文比较 | 重做 TTS |
| 音画时长 | 毫秒级时长和时间戳检查 | 重封装或修复音轨 |
| 黑帧/花屏 | FFmpeg 帧检测 | 自动重试 |
| 一分钟稳定性 | 每 5 秒抽帧 + 首尾身份比较 | 拆成 2–4 段重做 |

## 九、推荐的 PoC

不要只测试一张“最漂亮”的人物图。准备 6 组输入：

1. 正面胸像男性 + 演播室。
2. 正面胸像女性 + 办公室椅子。
3. 戴眼镜人物。
4. 有胡须人物。
5. 长发人物。
6. 场景中有桌子、椅子和品牌色的复杂背景。

每组使用同一条 60 秒中文音频，测试：

- Hedra Avatar。
- HeyGen Photo Avatar。
- D-ID。
- SoulX-FlashHead Lite。
- MuseTalk 动作模板方案。

评分权重：

| 指标 | 权重 |
|---|---:|
| 人物一致性 | 20% |
| 中文口型 | 20% |
| 一分钟稳定性 | 15% |
| 头部/眨眼/呼吸自然度 | 15% |
| 人物与场景融合 | 10% |
| 一次生成成功率 | 10% |
| 每可用分钟成本 | 5% |
| 生成时间 | 5% |

记录“每条最终可用视频的总成本”，包括失败重试，不只记录单次 API 标价。

## 十、分阶段落地建议

### 阶段 1：一到两周，先验证产品

```text
多参考图像编辑服务
  + MiniMax/CosyVoice TTS
  + Hedra Avatar
  + 字幕/FFmpeg
```

只实现四项用户输入，内部生成一张起始图和一条最终音频。用 HeyGen 和 D-ID 做离线质量对照，不全部接入产品。

### 阶段 2：验证自建

并行部署：

- SoulX-FlashHead Lite。
- MuseTalk 1.5。
- 3–5 个内部授权的坐姿动作模板。

用阶段 1 积累的真实任务做盲评和成本核算。

### 阶段 3：按业务量迁移

- 低用量：继续使用 Hedra，避免维护 GPU。
- 中等用量：商业服务与自建双路，失败时自动回退。
- 高用量/隐私要求：MuseTalk/FlashHead 自建为主，Hedra/HeyGen 作为精品或故障回退。

## 十一、最终推荐

如果现在只能确定一条方案：

> **用一个多参考图像编辑模型把人物图与场景图合成为固定坐姿起始图；用 CosyVoice 3 或 MiniMax Speech 根据声音样本和口播内容生成最终一分钟音频；用 Hedra Avatar 一次生成完整口播；字幕、Logo 和音频在后期完成。**

同时用少量样本验证 SoulX-FlashHead Lite，作为未来自建替代。不要在第一版使用 Seedance/Kling 逐段生成整分钟，也不要因为 LongCat 能做更多身体动作，就让固定坐姿场景承担不必要的 13B 视频扩散成本。

验收后再决定：

- 如果 Hedra 效果最好且业务量不大，直接继续使用。
- 如果 HeyGen 明显更稳定，接受约 $3/分钟换供应商。
- 如果 D-ID 已满足业务观感，选择其约 $0.69–0.78/分钟的低价路线。
- 如果月生成量大、隐私重要或需要完全掌控，投入 SoulX-FlashHead/MuseTalk 自建。
